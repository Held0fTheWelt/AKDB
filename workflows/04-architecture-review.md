# Workflow: architecture review

AKDB can support a review package for a proposed feature or refactoring.

## Review package

1. Relevant architectural decisions
2. Affected diagrams and source areas
3. Known drift and stale-knowledge signals
4. Constraints and guardrails
5. Open questions and ownership
6. Evidence and provenance

This gives reviewers a shared starting point and gives coding agents a bounded, explainable context.

## Review outcome

This is a synthetic workflow description, not an observed customer result. Present
the findings in a human-readable summary while retaining their source references.
Record which questions were answered, which relationships remain uncertain and
which sources were unavailable. The reviewer can then accept the bounded conclusion,
request more evidence or keep the decision open.

A completed report does not approve the proposed change. Likewise, a synthetic
check, a build result and a device observation retain their own qualification scopes.
